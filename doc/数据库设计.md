# 数据库设计（SQLite · GORM）

| 项 | 内容 |
| --- | --- |
| ORM | GORM v2（`gorm.io/gorm`） |
| 驱动 | `github.com/glebarez/sqlite`（纯 Go，底层 `modernc.org/sqlite`，无 CGO） |
| 文件 | `data/app.db`（WAL） |
| 模型 | `internal/domain/*.go`，数据访问在 `internal/store/*.go` |
| 建表 | `AutoMigrate`（模型即结构定义）+ 少量补充 DDL（组合索引/部分唯一索引） |
| 时间 | Go 侧统一 UTC，驱动以文本存储，展示层转本地时区 |

## 1. 连接与 GORM 配置

```go
// internal/store/db.go
func Open(path string) (*gorm.DB, error) {
    dsn := "file:" + filepath.ToSlash(path) +
        "?_pragma=journal_mode(WAL)" +
        "&_pragma=busy_timeout(5000)" +
        "&_pragma=foreign_keys(1)" +
        "&_pragma=synchronous(NORMAL)" +
        "&_pragma=temp_store(MEMORY)"

    db, err := gorm.Open(sqlite.Open(dsn), &gorm.Config{
        PrepareStmt:            true,  // 预编译语句缓存
        SkipDefaultTransaction: true,  // 单条写不自动包事务，多表写显式 Transaction
        TranslateError:         true,  // 驱动错误 → gorm.ErrDuplicatedKey 等
        NowFunc:                func() time.Time { return time.Now().UTC() },
        Logger:                 gormLogger(), // 接入 slog，慢查询 >200ms 记 warn
    })
    if err != nil {
        return nil, fmt.Errorf("open sqlite: %w", err)
    }

    sqlDB, err := db.DB()
    if err != nil {
        return nil, err
    }
    sqlDB.SetMaxOpenConns(8)
    sqlDB.SetMaxIdleConns(8)
    sqlDB.SetConnMaxLifetime(0)
    return db, nil
}
```

要点：

- `foreign_keys(1)` 必须开启，否则外键约束不生效。
- `busy_timeout` 交给 SQLite，避免瞬时写冲突直接报错。
- `SkipDefaultTransaction=true` 提升单条写性能，但**跨表写必须显式事务**。
- 不启用 GORM 的 `SingularTable`，表名使用默认复数（`users`、`papers`…），与文档一致。

## 2. 命名与字段约定

| 项 | 约定 |
| --- | --- |
| 表名 | 默认复数：`users`、`subjects`、`ai_providers`、`papers`、`paper_files`、`questions`、`attempts`、`attempt_answers`、`jobs`、`ai_calls`、`settings`、`audit_logs` |
| 主键 | 自增 `int64`；`files.id`、`jobs.id` 用 UUID 字符串 |
| 外键 | `<关联>ID`，显式声明 `constraint`，删除策略写在关联 tag 上 |
| 枚举 | `string` + Go 常量 + `check` tag；Service 层再做一次校验 |
| 布尔 | `bool`（SQLite 存 0/1），`default:false` 明确写出 |
| 可空时间 | `*time.Time`；非空用 `time.Time` + `autoCreateTime/autoUpdateTime` |
| 金额/分值 | `float64`，比较用容差 `1e-6`，展示保留 1 位小数 |
| JSON 字段 | 自定义类型（`StringList`/`OptionList`/`ReportMap`）实现 `driver.Valuer` + `sql.Scanner`，DB 中为 TEXT |
| 软删除 | 仅 `users` 使用 `gorm.DeletedAt`；其余表物理删除或状态归档 |

```go
// internal/domain/json.go
type StringList []string

func (s StringList) Value() (driver.Value, error) {
    if s == nil {
        return "[]", nil
    }
    b, err := json.Marshal(s)
    return string(b), err
}

func (s *StringList) Scan(v any) error {
    switch x := v.(type) {
    case nil:
        *s = StringList{}
        return nil
    case []byte:
        return json.Unmarshal(x, s)
    case string:
        return json.Unmarshal([]byte(x), s)
    default:
        return fmt.Errorf("unsupported type %T for StringList", v)
    }
}
```

`OptionList`（`[]Option{Key,Text}`）、`ReportMap`（`map[string]any`）同理。

## 4. GORM 模型

### 4.1 User

```go
type User struct {
    ID            int64          `gorm:"primaryKey;autoIncrement"`
    Username      string         `gorm:"type:text;not null;uniqueIndex:ux_users_username"`
    PasswordHash  string         `gorm:"type:text;not null"`
    DisplayName   string         `gorm:"type:text;not null"`
    Role          string         `gorm:"type:text;not null;check:chk_users_role,role IN ('teacher','student')"`
    ClassName     string         `gorm:"type:text;not null;default:''"`
    Grade         string         `gorm:"type:text;not null;default:''"`
    Phone         string         `gorm:"type:text;not null;default:''"`
    Status        int            `gorm:"not null;default:1"` // 1 启用 / 0 禁用
    TokenVersion  int            `gorm:"not null;default:0"`
    MustChangePwd bool           `gorm:"not null;default:false"`
    LastLoginAt   *time.Time
    CreatedAt     time.Time      `gorm:"not null;autoCreateTime"`
    UpdatedAt     time.Time      `gorm:"not null;autoUpdateTime"`
    DeletedAt     gorm.DeletedAt `gorm:"index:ix_users_deleted"`
}

func (User) TableName() string { return "users" }
```

- **用户名唯一索引包含软删除行**：删除后该用户名不可复用（避免历史数据指向歧义）；如需复用，改为"部分唯一索引 + 物理改名"策略。
- 登录查询自动排除 `deleted_at` 行（GORM 软删除默认行为）。

## 5. 迁移与 Seed

### 5.1 执行顺序

```go
// internal/store/migrate.go
func Migrate(db *gorm.DB) error {
    if err := db.AutoMigrate(
        &domain.Subject{}, &domain.User{}, &domain.AIProvider{}, &domain.File{},
        &domain.Paper{}, &domain.PaperFile{}, &domain.Question{},
        &domain.Attempt{}, &domain.AttemptAnswer{},
        &domain.Job{}, &domain.AICall{}, &domain.Setting{}, &domain.AuditLog{},
    ); err != nil {
        return fmt.Errorf("automigrate: %w", err)
    }
    for _, stmt := range extraDDL {
        if err := db.Exec(stmt).Error; err != nil {
            return fmt.Errorf("extra ddl: %w", err)
        }
    }
    return seed(db)
}
```

`extraDDL`（GORM tag 无法表达的组合/部分索引，幂等执行）：

```sql
CREATE INDEX IF NOT EXISTS ix_users_role_status ON users (role, status);
CREATE INDEX IF NOT EXISTS ix_users_class ON users (class_name);
CREATE INDEX IF NOT EXISTS ix_papers_subject ON papers (subject_id, status, created_at DESC);
CREATE INDEX IF NOT EXISTS ix_papers_status ON papers (status, created_at DESC);
CREATE INDEX IF NOT EXISTS ix_papers_created_by ON papers (created_by, created_at DESC);
CREATE INDEX IF NOT EXISTS ix_questions_paper ON questions (paper_id, seq);
CREATE INDEX IF NOT EXISTS ix_attempts_student ON attempts (student_id, status, started_at DESC);
CREATE INDEX IF NOT EXISTS ix_attempts_paper ON attempts (paper_id, status);
CREATE INDEX IF NOT EXISTS ix_jobs_status ON jobs (status, created_at);
CREATE UNIQUE INDEX IF NOT EXISTS ux_jobs_active_ref
    ON jobs (type, ref_type, ref_id) WHERE status IN ('pending', 'running');
CREATE INDEX IF NOT EXISTS ix_ai_calls_created ON ai_calls (created_at);
CREATE INDEX IF NOT EXISTS ix_ai_calls_purpose ON ai_calls (purpose, created_at);
CREATE INDEX IF NOT EXISTS ix_audit_actor ON audit_logs (actor_id, created_at);
```

> `ux_jobs_active_ref` 保证同一试卷/答卷同时只有一个活动任务；`ref_id=0` 的任务（无关联）需要业务侧避免并发创建。

### 5.2 版本策略

| 场景 | 做法 |
| --- | --- |
| 新增表 / 列 / 索引 | 改模型 → 启动 `AutoMigrate` 自动完成（只增） |
| 修改 CHECK / 约束、删列、改名 | SQLite 不支持直接 ALTER：新建迁移文件 `internal/store/migrations/NNN_xxx.sql`，用 `schema_migrations` 表记录版本，手工执行"建新表 → 迁数据 → 换名" |
| 数据修复/回填 | 写 `dataMigrations`（Go 函数 + `settings['data.version']` 幂等执行） |
| 旧程序打开新库 | 启动时比对 `settings['schema.version']`，二进制版本低则拒绝启动 |
| 已发布版本的破坏性变更 | 保留一个版本的兼容代码，禁止直接删字段 |

```sql
-- 仅在需要破坏性变更时启用
CREATE TABLE IF NOT EXISTS schema_migrations (
    version    INTEGER PRIMARY KEY,
    name       TEXT NOT NULL,
    applied_at TEXT NOT NULL
);
```

### 5.3 Seed（幂等）

1. 科目：`CreateInBatches` + `clause.OnConflict{Columns: [stage,name], DoNothing: true}`。
2. 默认设置：`ON CONFLICT (key) DO NOTHING` 写入 `system.version`、`ai.role.*` 默认空值等。
3. 初始老师账号：`users` 无 teacher 时创建 `admin`，随机密码仅在启动日志打印一次，`must_change_pwd=1`。
4. 所有 seed 必须在事务内执行，失败则启动失败（避免半初始化）。

[
  {"key": "A", "text": "2 或 3"},
  {"key": "B", "text": "-2 或 -3"},
  {"key": "C", "text": "1 或 6"},

### 6.2 `attempts.report`（`ReportMap`）

```json
{
  "version": 1,
  "generated_by": "local+ai",
  "accuracy": 0.72,
  "score_rate": 0.78,
  "duration_sec": 3560,
  "weak_points": [
    {"knowledge": "一元二次方程", "wrong": 3, "total": 5},
    {"knowledge": "判别式", "wrong": 2, "total": 3}

  "suggestions": [

  ],

```

### 6.3 `attempt_answers.answer`

与 `questions.answer` 同构的 `StringList`；未作答为 `[]`；填空 `["", "x=2"]` 表示部分空白。

### 6.4 数学作答内容格式（LaTeX）

主观题（`short`）答案存为**单个字符串**（`StringList` 长度 1），内容是"文本 + 行内/独立公式"的 Markdown-lite：

| 规则 | 说明 |
| --- | --- |
| 行内公式 | `$latex$`，如 `由 $x^2-5x+6=0$ 得 $(x-2)(x-3)=0$` |
| 独立公式 | `$$latex$$` 独占一行，前后各一个换行 |
| 换行 | `\n`；不使用 `<br>` |
| 字面量美元符 | 转义为 `\$` |
| HTML | 禁止；服务端按纯文本存储，展示前由客户端渲染 |
| 长度 | 整题 ≤16KB（服务端校验）；单个公式源码 ≤4KB（前端提示，不阻断提交） |
| LaTeX 来源 | MathLive 输出（`getValue('latex')`）；老师端同源 |
| 表单 | 不使用 `\begin{align}` 等复杂环境（KaTeX 不支持时降级纯文本），需要换行用多个 `$$...$$` |

示例（解答题）：

```json
{
  "question_id": 112,
  "answer": [
    "解：由题意得\n$$x^2-5x+6=0$$\n因式分解得 $(x-2)(x-3)=0$，所以\n$$x_1=2,\\ x_2=3$$"
  ]
}
```

填空（数学）示例：

```json
{ "question_id": 105, "answer": ["\\frac{1}{2}", "x>1"] }
```

判分相关约定：

- 规范化顺序：去首尾空白 → 去除 `\left`/`\right`/`\,`/`\;`/`\!` → `\dfrac`→`\frac` → 合并连续空白 → 全角转半角。
- 多空答案按空位顺序逐项比较，不合并。
- 规范化后不等且包含 LaTeX 时，进入 AI 等价判定（用途 `equiv`），结果按 `attempt_answer` 维度缓存，避免重复计费。
- `\text{...}` 中的中文按普通文本比较；大小写、单位空格不敏感。
- 公式源码不参与数据库全文检索；如需按知识点检索，用 `knowledge` 字段。

## 7. 常用 GORM 写法

### 7.1 分页列表（同条件计数）

```go
func (r *PaperRepo) List(ctx context.Context, f PaperFilter, page, size int) ([]domain.Paper, int64, error) {
    q := r.db.WithContext(ctx).Model(&domain.Paper{}).
        Where("status = ?", f.Status)
    if f.SubjectID > 0 {
        q = q.Where("subject_id = ?", f.SubjectID)
    }
    if f.Keyword != "" {
        q = q.Where("title LIKE ?", "%"+f.Keyword+"%")
    }

    var total int64
    if err := q.Count(&total).Error; err != nil {
        return nil, 0, err
    }

    var items []domain.Paper
    err := q.Preload("Subject").
        Order("created_at DESC").
        Limit(size).Offset((page - 1) * size).
        Find(&items).Error
    return items, total, err
}
```

> `LIKE` 关键词需转义 `%`/`_`；排序字段用白名单映射，禁止用户输入直接进 `Order()`。

### 7.2 答题自动保存（幂等 upsert）

```go
func (r *AttemptRepo) UpsertAnswers(ctx context.Context, rows []domain.AttemptAnswer) error {
    if len(rows) == 0 {
        return nil
    }
    return r.db.WithContext(ctx).
        Clauses(clause.OnConflict{
            Columns:   []clause.Column{{Name: "attempt_id"}, {Name: "question_id"}},
            DoUpdates: clause.AssignmentColumns([]string{"answer", "updated_at"}),
        }).
        CreateInBatches(&rows, 50).Error
}
```

### 7.3 开始答卷（并发安全）

```go
att := domain.Attempt{PaperID: paperID, StudentID: sid, AttemptNo: nextNo, Status: "in_progress", StartedAt: now}
err := db.WithContext(ctx).Clauses(clause.OnConflict{DoNothing: true}).Create(&att).Error
if errors.Is(err, gorm.ErrDuplicatedKey) || att.ID == 0 {
    // 已存在相同 attempt_no，回查返回（幂等）
}
```

### 7.4 提交（多表写，显式事务）

```go
err := db.WithContext(ctx).Transaction(func(tx *gorm.DB) error {
    // 1. 锁定状态：UPDATE attempts SET status='submitted' WHERE id=? AND status='in_progress'
    // 2. 写 attempt_answers 分数
    // 3. 汇总 objective_score / correct_count
    // 4. 需要 AI 阅卷时置 status='grading' 并插入 jobs
    return nil
})
```

- SQLite 无 `SELECT ... FOR UPDATE`，用条件更新（`WHERE status='in_progress'`）判断 `RowsAffected` 实现乐观锁，避免重复提交。
- 事务内不要做网络调用（AI 调用只在 worker 中）。

### 7.5 统计（Raw + 参数绑定）

```go
type knowledgeStat struct {
    Knowledge string  `gorm:"column:knowledge"`
    Wrong     int     `gorm:"column:wrong"`
    Total     int     `gorm:"column:total"`
}

err := db.WithContext(ctx).Raw(`
    SELECT json_extract(k.value, '$') AS knowledge,
           SUM(CASE WHEN aa.is_correct = 0 THEN 1 ELSE 0 END) AS wrong,
           COUNT(*) AS total
    FROM attempt_answers aa
    JOIN questions q ON q.id = aa.question_id
    JOIN json_each(q.knowledge) k
    WHERE aa.attempt_id = ?
    GROUP BY knowledge
    ORDER BY wrong DESC
    LIMIT 5`, attemptID).Scan(&rows).Error
```

> 需要 `json1` 扩展（`modernc.org/sqlite` 已内置）。若统计逻辑变复杂，改为在 Go 侧聚合（数据量小）。

### 7.6 错误映射

```go
func mapDBError(err error) error {
    switch {
    case errors.Is(err, gorm.ErrRecordNotFound):
        return NewAppError(http.StatusNotFound, 1004, "资源不存在")
    case errors.Is(err, gorm.ErrDuplicatedKey):
        return NewAppError(http.StatusConflict, 1005, "数据已存在")
    default:
        return fmt.Errorf("db: %w", err)
    }
}
```

需在 `gorm.Open` 时设置 `TranslateError: true`，否则拿不到 `gorm.ErrDuplicatedKey`。

## 8. 数据一致性规则

1. 题目 `seq` 在试卷内唯一；增删题后由 Service 在一个事务内重排并同步 `papers.question_count`、`papers.total_score`。
2. `attempts.full_score` 在提交时快照；`attempt_answers.max_score` 在提交时快照题目分值，后续改卷不影响历史成绩。
3. 归档用 `papers.status='archived'`；有作答记录的试卷禁止物理删除（`attempts.paper_id` 外键 `RESTRICT`）。
4. AI 阅卷失败不回滚已判客观题分数；`attempts.status='graded'`，`grade_error` 记录待人工复核题目。
5. 涉及多表写入（提交答卷、生成报告、发布试卷、解析入库）必须单事务。
6. 软删除的用户不参与登录与列表；历史 `attempts` 保留并可查（`Unscoped()` 仅老师端报告使用）。
7. 时间统一 UTC 写入；SQL 文本比较依赖同一格式，禁止混入本地时区时间。
8. 删除 AI provider 时解除 `settings` 中角色绑定并回落到 `ai.default`，`ai_calls` 保留历史。

## 9. 性能与运维

| 项 | 建议 |
| --- | --- |
| 写入 | 批量 `CreateInBatches`（50~200/批）；单题保存合并为一次 upsert |
| 读取 | 列表只查必要列（`Select`），详情用 2 次查询组装，禁用深层 `Preload` |
| 索引 | 以 §5.1 的 `extraDDL` 为准；新增查询先看执行计划 `EXPLAIN QUERY PLAN` |
| 锁等待 | `busy_timeout=5000`；捕获 busy 错误后重试 2 次（100ms/300ms） |
| 体积 | 定期 `PRAGMA wal_checkpoint(TRUNCATE)`；`PRAGMA optimize` 每周一次 |
| 备份 | 停写或 checkpoint 后复制 `app.db`（+`-wal`/`-shm`）与 `uploads/` |
| 迁移安全 | 升级前备份；`AutoMigrate` 仅做增量，破坏性变更走版本化 SQL |
| 日志 | GORM 慢查询阈值 200ms，记录 SQL、耗时、影响行数（不记录参数中的敏感值） |

### 已知限制（GORM + SQLite）

- `AutoMigrate` 不会删除列/索引，也不会修改已有 CHECK 约束；需要时走手工迁移。
- SQLite 单写者：高并发写依赖短事务 + busy 重试，不做分库分表。
- 无原生 JSON 列类型：JSON 以 TEXT 存储，查询用 `json_each`/`json_extract`，复杂分析放 Go。
- 驱动不支持 `SELECT FOR UPDATE`：用条件更新 + `RowsAffected` 做乐观锁。
- 时间字段由驱动序列化为文本，跨库比较时统一 UTC。
