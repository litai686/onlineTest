## 1. 项目概述

### 1.1 目标

为初中 / 高中场景提供一套"老师出卷 → 学生做题 → AI 阅卷 → 学情建议"的闭环系统。老师可以上传图片或 PDF 试卷，由 AI 识别成结构化题目入库；学生无需注册，账号由老师创建；学生在线作答后，系统自动判分（客观题本地判分、主观题 AI 阅卷）并生成个人总结与学习建议。

### 1.2 范围（本期必做）

- 老师端：登录、学生管理、AI 模型配置（OpenAI 兼容接口，可增删改）、试卷科目管理（初中 / 高中数学优先，预留其他学段科目）、试卷上传（图片 / PDF）、AI 识别入库、试卷手工编辑与发布。
- 学生端：登录、试卷列表、在线答题（自动保存）、提交判分、查看成绩与 AI 评审报告、历史记录。
- 基础设施：JWT 认证（默认 30 天）、SQLite（GORM + 纯 Go 驱动）、前端资源 `go:embed` 内嵌、异步任务（解析 / 阅卷）与调用日志。

### 1.3 非目标（本期不做，架构上预留）

- 在线考试监考（防切屏、摄像头抓拍、限时强制交卷的强管控）。
- 多学校 / 多租户、组织架构、教师协作与审批流。
- 移动端 App、微信登录、短信验证码。
- 题库跨卷复用与智能组卷（本期题目归属于试卷，表结构预留可迁移）。
- 支付、消息推送、统计大屏（先做基础统计接口）。

## 2. 技术选型

| 层 | 选型 | 说明 |
| --- | --- | --- |
| 语言 | Go 1.26.4 | 单二进制，交叉编译 |
| HTTP | 标准库 `net/http` + `http.ServeMux`（Go 1.22+ 方法/路径模式） | 不引框架，减少依赖 |
| 数据库 | GORM v2（`gorm.io/gorm`）+ `github.com/glebarez/sqlite` | 纯 Go 驱动（底层 modernc.org/sqlite，无 CGO），WAL；数据操作全部用 GORM，建表由 AutoMigrate 完成 |
| 认证 | `github.com/golang-jwt/jwt/v5`，HS256 | 默认 30 天有效期，`token_version` 支持强制下线 |
| 密码 | `golang.org/x/crypto/bcrypt` | cost 10 |
| 前端 | 原生 HTML + CSS + ES Modules，零框架零构建 | `//go:embed web` 内嵌 |
| 数学公式 | 渲染 KaTeX + 输入 MathLive（均 vendor 为静态 ESM，零构建） | 题干/答案用 KaTeX 只读渲染；学生作答用 MathLive 公式编辑器（虚拟键盘 + LaTeX 输出） |
| 日志 | 标准库 `log/slog`（JSON 或 Text） | 请求日志 + 业务日志 + 慢查询 |
| 测试 | 标准库 `testing` + `httptest` + mock LLM 服务 | 不引第三方测试框架 |

> 直接依赖控制在 5 个左右（gorm、glebarez/sqlite、jwt、bcrypt、PDF 文本抽取）；所有第三方库在 `go.mod` 中锁定版本。

### 3.3 关键运行约束

- 单进程多 goroutine；SQLite 单写者，必须 `WAL + busy_timeout=5000`，写操作走事务并尽量短。
- 所有请求默认超时 30s；AI 请求单独超时（默认 120s，可配）。
- GORM 配置：`PrepareStmt: true`、`SkipDefaultTransaction: true`（单条写不自动包事务，多表写显式 `db.Transaction`）、`NowFunc` 统一 UTC。
- 连接池 `SetMaxOpenConns(8)`；批量写入用 `CreateInBatches` / `clause.OnConflict`，禁止在循环里逐条写。
- 前端资源与迁移脚本 `go:embed`，运行时不依赖源码目录。
- 数据目录可配置，便于备份和迁移；同目录不允许启动两个实例（文件锁，P1）。

### 3.4 请求链路约定

1. 中间件：`recover → requestID → 日志 → CORS → 限流(登录) → JWT → 角色校验`。
2. Handler 只做参数绑定与校验，业务在 Service，GORM 查询集中在 Store（Repository），Handler/Service 不直接持有 `*gorm.DB`。
3. 统一响应 `{"code":0,"message":"ok","data":...}`；错误用 `code` 区分业务语义（见 API 文档）。
4. 分页统一 `page`（从 1 开始）、`page_size`（默认 20，最大 100），返回 `{items,total,page,page_size}`。

### 3.5 数据访问约定（GORM）

- 模型定义在 `internal/domain`，只用于持久化；对外响应用独立 DTO，禁止把 `password_hash`、`api_key_cipher` 直接序列化。
- 每个聚合一个 Repository（`Users`/`Papers`/`Attempts`/…），方法首参 `ctx context.Context`，内部统一 `r.db.WithContext(ctx)`。
- 事务：`db.WithContext(ctx).Transaction(func(tx *gorm.DB) error { ... })`；跨 Repository 的事务由 Service 用 `store.New(tx)` 创建事务内 Repository。
- 错误：`gorm.ErrRecordNotFound` → `AppError{1004}`；唯一约束冲突识别驱动错误后转 `1005`，不向前端暴露 SQLite 原文。
- 列表：`Where(...).Order(...).Limit().Offset().Find()` + 同条件 `Count()`；复杂统计用 `db.Raw()` 但必须参数绑定，排序字段白名单映射。
- 幂等写：答题保存用 `clause.OnConflict{Columns: [attempt_id, question_id], DoUpdates: ...}`；开始答卷靠唯一索引 + `OnConflict{DoNothing}` 后回查。
- 软删除：`gorm.DeletedAt`（`users.deleted_at`），查询默认排除；仅管理/审计场景用 `Unscoped()`。
- 关联：只在必要时 `Preload`，列表页禁止 N+1；试卷详情用 2 次查询（试卷 + 题目）组装。
- 禁止：字符串拼接 SQL、`Raw` 传用户输入、Handler 内写查询、用 `AutoMigrate` 做破坏性结构变更（删列/改约束/改名，见数据库设计 §5）。

## 5. 功能模块设计

### 5.1 老师端

#### 5.1.1 登录
- 用户名 + 密码，bcrypt 校验，签发 JWT（30 天）。
- 连续失败 5 次锁定 10 分钟（内存计数 + 日志，P1）。
- 首次启动 seed 一个老师账号，密码打印到日志，登录后提示修改。

#### 5.1.2 学生管理
- 列表：关键字（用户名/姓名）、班级、状态、分页。
- 新建：用户名（唯一，登录名）、姓名、班级、年级、初始密码（可自动生成并回显一次）。
- 编辑：姓名、班级、年级、状态（启用/禁用）、重置密码。
- 删除：软删除（`deleted_at`），保留历史作答；禁用后其 JWT 因 `token_version` 失效。
- CSV 批量导入（P2）。

#### 5.1.3 AI 模型配置
- 支持任意 OpenAI 兼容服务（base_url + api_key + model），可增删改。
- 能力开关：视觉（图片识别）、温度、超时、并发上限、额外请求头/请求体（JSON 透传）；JSON 输出默认启用，不发送 `max_tokens`，使用服务商默认值。
- 角色绑定（写 `settings` 表）：
  - `ai.role.vision`：试卷图片/PDF 识别
  - `ai.role.grading`：主观题阅卷与报告
  - `ai.role.chat`：连通性测试与通用能力
  - 未绑定时回落到"默认 provider"。
- "测试"按钮：发一条最小请求，返回延迟、模型名、是否支持视觉（探测失败则按文本处理并提示）。
- API Key 使用 AES-256-GCM 加密存储，密钥来自 `ONLINETEST_SECRET` 或 `data/.secret`（首次生成，0600）；列表接口只回显末 4 位。
- 所有调用写 `ai_calls`（耗时/token/状态），老师端可查看最近调用，便于排查额度与限流问题。

#### 5.1.4 试卷科目管理
- 维度：学段（`junior` / `senior`）× 科目名。默认 seed：
  - 初中：语文、数学、英语、物理、化学、生物、历史、地理、政治
  - 高中：语文、数学、英语、物理、化学、生物、历史、地理、政治
- 排序、启用/禁用；被试卷引用时禁止删除（返回提示）。

#### 5.1.5 试卷管理与上传
- 列表：科目/学段/状态/关键字筛选，展示题数、总分、解析状态。
- 新建试卷（手工）：标题、科目、学段、年级、时长、说明。
- 上传解析：
  1. 选择文件（1~N 张图片或 1 个 PDF，单文件 ≤20MB）。
  2. 创建试卷（`status=draft, parse_status=queued`）与 `jobs` 任务，立即返回 `job_id`。
  3. 前端轮询 `GET /api/v1/jobs/{id}` 展示进度（页数/题目数）。
  4. Worker：图片 → base64 data URL → 视觉模型输出结构化 JSON；PDF → 先抽文字层，有文字则文本模式 + 视觉兜底，无文字层则提示"扫描版 PDF，请上传截图"。
  5. 结果落库为题目草稿（`ai_confidence` 记录置信度），试卷转 `ready`。
- 解析结果校对页：题目列表可编辑（题干、选项、答案、分值、解析、知识点、题型），支持排序、删除、手动加题；校验总分 = 各题之和。
- 发布：校验（题目数 > 0、每题有答案或标明人工阅卷、分值合计 > 0）后 `published`，学生端可见；可归档。缺答案题目应在识别入库阶段由 AI 补全。
- 修改已发布试卷：允许改标题/说明/时长；题目变更提示"已影响 N 份作答"，需二次确认（P1）。

#### 5.1.6 成绩与报告查看
- 按试卷查看提交列表（学生、提交时间、得分、状态）。
- 单份报告详情：逐题得分、AI 评语、整卷总结与建议。
- 手动复判（改分）与触发生成报告（P1）。

### 5.2 学生端

#### 5.2.1 登录
- 无注册入口。老师创建账号后凭用户名 + 密码登录，JWT 30 天。
- 被禁用/删除的账号登录返回明确提示；旧令牌因 `token_version` 变化失效。

#### 5.2.2 试卷列表
- 展示已发布且未归档的试卷：标题、科目、题数、总分、时长、我的作答状态（未做/进行中/已提交/已阅卷）。
- 支持按科目筛选。

#### 5.2.3 做题页
- 左侧题号导航（答题卡：已答/未答/标记），右侧题目区；单页滚动或逐题切换（默认单页滚动，题干长时体验更好）。
- 题型控件：单选（radio）、多选（checkbox）、判断（radio 对/错）、填空（一个或多个输入框；数学科目启用公式输入）、简答（公式作答器，见 §5.2.5）。
- 自动保存：输入防抖 2s + 切题/离开页面 `sendBeacon`；后端幂等 upsert。
- 计时：基于 `started_at` 计算，刷新不丢；时长到点前端提示并可自动提交（P1，由老师端开关控制）。
- 提交：确认弹窗 → `POST submit` → 状态 `submitted`，后台判分 → 前端轮询结果页。
- 公式渲染：题干、选项、答案中的 `$...$` 由 KaTeX 渲染（`throwOnError:false`、`trust:false`），失败片段降级为纯文本。

#### 5.2.4 结果与报告
- 总分 / 满分 / 用时 / 正确题数；客观题即时出分，主观题显示"AI 阅卷中"。
- 逐题：我的答案、正确答案（按试卷配置是否展示）、得分、AI 评语、改进建议。
- 整卷报告：得分率、薄弱知识点 Top3、总体评价、下一步学习建议（3~5 条）。
- 历史记录列表，可按试卷/时间筛选。

#### 5.2.5 数学公式输入方案

**目标**：解答题（计算/证明）能像 Word 公式一样边写文字边写公式；填空可直接录入公式；提交后 AI 能正确理解并判分。

**选型**

| 方案 | 结论 | 说明 |
| --- | --- | --- |
| MathLive | ✅ 采用 | Web Component，内置虚拟键盘、输出 LaTeX，MIT 许可，可离线 vendor |
| KaTeX | ✅ 展示用 | 只读渲染题干/选项/答案，同步渲染、体积小 |
| MathQuill | ❌ | 依赖 jQuery，维护停滞，移动端一般 |
| 纯 LaTeX 文本框 | ❌ | 学生门槛过高 |
| 拍照手写作答 | P2 | 兜底方案，AI OCR 转 LaTeX 后需学生确认 |

**资源与组件**
- `web/vendor/mathlive/`（`mathlive.min.mjs` + `mathlive-fonts.css` + fonts + sounds）、`web/vendor/katex/`（`katex.mjs` + `katex.min.css` + fonts）全部为静态文件，`index.html` 不直接引用，仅在做题页/题目编辑器动态 `import()`（首次进入约 1 次加载，之后缓存）。
- `math-render.js`：把含 `$...$`、`$$...$$` 的文本渲染为 DOM（KaTeX `throwOnError:false`、`trust:false`、`maxExpand:1000`），失败片段退化为 `<code>`。
- `math-input.js`：作答编辑器，对外暴露 `getValue() / setValue() / focus() / onChange()`，供做题页与老师题目编辑器复用。

**作答交互（核心）**
- v1 实现：每题一个多行文本域，学生先写文字，点「公式」打开 MathLive 浮层编辑，确认后插入 `$latex$`；右侧/下方可切换 KaTeX 预览。文本与公式按 §5.2.5 的序列化规则保存，天然支持刷新恢复与 AI 阅卷。
- P1 增强：升级为 `contenteditable` 内联公式芯片（公式作为不可编辑节点混排在文字中，双击回编辑），交互更接近 Word；组件接口 `getValue/setValue` 保持不变，做题页与老师编辑器无需改动。
- 工具栏：插入行内公式（Ctrl/⌘+E）、插入独立公式、常用模板（分式、根号、幂、下标、绝对值、不等式、方程组、矩阵、积分、求和、π、角度、单位）。
- 点击公式节点 → 弹出 MathLive 编辑器（移动端全屏抽屉），确认后回写 `data-latex` 并重渲染；双击可快速再编辑。
- 移动端：MathLive 虚拟键盘默认弹出（数字/字母/希腊字母/运算符分页），手写识别开关（P2）。
- 粘贴：一律按纯文本插入；识别 `$...$`、`\[...\]`、以 `\` 开头的裸 LaTeX 自动转公式节点，不解析 HTML（防 XSS）。
- 预览：编辑/预览切换，预览用 `math-render.js` 渲染最终文本。
- 序列化：遍历子节点，文本原样拼接，公式节点输出 `$latex$`，独立公式输出 `$$latex$$`；换行统一 `\n`；字面量美元符转义 `\$`。反序列化按 `$` 规则切回节点。
- 限制：整题答案 ≤16KB（服务端硬限制）；单个公式源码 ≤4KB（前端提示，不阻断提交）。
- 降级：MathLive 加载失败或浏览器不支持时，退化为 textarea + "插入公式"（LaTeX 源码）+ KaTeX 预览，保证始终可作答。

**填空/客观题**
- 数学科目填空题用单行 MathLive 输入（可切换纯文本），答案存 LaTeX；多空为多个输入框，按空位顺序存 `StringList`。
- 单选/多选/判断不涉及公式输入，只渲染。

**与阅卷的衔接**
- 提示词显式声明："学生答案可能包含 LaTeX（`$...$`），按数学含义评分，忽略排版差异；等价表达（如 `\frac{1}{2}` 与 `0.5`）不扣分。"
- 填空本地判分先规范化（去 `\left`/`\right`/`\,`/空白，`\dfrac`→`\frac`，全角转半角）；仍不等且含 LaTeX 时调用 AI 做等价判定（用途 `equiv`，结果缓存，失败按错处理并标记待复核）。
- AI 输出中的 LaTeX 展示前同样过 `math-render.js` 安全渲染。
- 老师端校对页、答案/解析编辑复用同一 `math-input.js`，保证"编辑所见 = 学生所见"。

**安全**
- KaTeX 关闭 `trust`，禁用 `\href`、`\url`、`\includegraphics`、`\html*`；`maxExpand` 限制宏展开；服务端只存纯文本，不存 HTML。
- 公式源码与请求体均有长度限制；渲染只在客户端，避免恶意公式拖慢服务端。
- XSS 用例覆盖 `\href{javascript:...}`、`\htmlStyle`、`<img onerror>` 粘贴。

**验收**
- 学生 30 秒内可完成"文字 + 分式 + 根号 + 方程组"的混合作答；
- 刷新后公式完整恢复且可再次编辑；
- 移动端 Chrome/Safari 虚拟键盘可输入常用符号；
- 提交后 AI 能正确理解 LaTeX 并给出合理评分。

### 5.3 AI 子系统

#### 5.3.1 客户端
- 接口：`POST {base_url}/chat/completions`，兼容 `messages`（`content` 支持 `[{type:"text"},{type:"image_url",image_url:{url:"data:image/jpeg;base64,..."}}]`）。
- 参数：`model`、`temperature`、`response_format:{type:"json_object"}`（JSON 输出默认启用）、`stream:false`；不发送 `max_tokens`。
- 重试：网络错误/5xx/429 指数退避重试 2 次（1s、3s）；4xx 不重试；总时长受超时约束。
- 并发：每个 provider 一个信号量，默认 2；超出排队。
- 日志：脱敏记录（不落 prompt 全文、不落 key），记录 token 用量与延迟。

#### 5.3.2 试卷识别（vision）
- 输入：图片（可为多页）+ 提示词（学段/科目/题量提示可选）。
- 输出（严格 JSON）：
  ```json
  {
    "title": "初二数学期中试卷",
    "stage": "junior",
    "grade": "初二",
    "subject": "数学",
    "duration_min": 120,
    "total_score": 100,
    "questions": [
      {
        "seq": 1,
        "type": "single",
        "stem": "若 $x^2-5x+6=0$，则 $x$ 的值为（ ）",
        "options": [{"key": "A", "text": "2 或 3"}, {"key": "B", "text": "-2 或 -3"}],
        "answer": ["A"],
        "score": 3,
        "analysis": "因式分解得 (x-2)(x-3)=0",
        "knowledge": ["一元二次方程"],
        "difficulty": "easy",
        "confidence": 0.92
      }
    ]
  }
  ```
- 处理策略：
  - 多图分批识别（每批 1~3 页，控制 token），按页序合并，`seq` 重排。
  - 若试卷含答案页 / 答案册：提示词要求分离题干与答案，答案缺失时 `answer=[]` 并标注 `need_manual`。
  - 解析失败：提取首个 `{...}` 平衡括号片段 → 仍失败则修复常见问题（去尾逗号、补引号）→ 再失败则任务失败并保留原始响应摘要供排查。
- 入库校验：题型枚举合法、单选答案唯一、分值 > 0、题干非空；非法题目进入"待校对"并标红。

#### 5.3.3 阅卷（grading）
- 客观题（单选/多选/判断/填空）本地判分：
  - 规范化：去首尾空白、全角转半角、大小写不敏感、多空按顺序；数学答案额外去 `\left`/`\right`/`\,`/空白、`\dfrac`→`\frac`。
  - 数学等价：字符串规范化后仍不等且含 LaTeX 时，调用 AI 等价判定（用途 `equiv`，低温度，结果缓存）；失败按错处理并标 "待复核"。
  - 多选：全对得分，漏选 0 分（默认；可配置半分，P1）。
- 主观题（简答/计算/证明）：AI 阅卷。
  - 单次批量 5 题以内：题目、参考答案、解析、满分、学生答案、评分要求（按步骤给分、允许等价表达、不得因排版扣分、学生答案可能含 LaTeX）。
  - 输出：`[{"question_id":12,"score":6,"is_correct":false,"feedback":"...","missing":["未讨论判别式"],"advice":"..."}]`
  - 分数钳制到 `[0, max]`，步长 0.5；`feedback` 限 120 字，避免长篇。
  - 失败降级：该题置 `grading_mode='manual'`，状态仍可完成，老师端显示"待人工复核"。
- 整卷报告：本地统计（得分率、正确率、知识点分布）+ AI 生成自然语言（总体评价、薄弱点、3~5 条建议、推荐练习方向）。
- 成本控制：题数上限/次、图片先压缩、温度 0.1~0.3、同题不重复调用（幂等键 `attempt_id+question_id`）。

#### 5.3.4 提示词管理
- 提示词写在 `internal/ai/prompt.go`，按版本号常量维护，改变时在调用日志 `request_digest` 中记录版本，便于回归对比。
- 系统提示统一要求：只输出 JSON、不要 Markdown 代码块、不确定的字段置空而非编造、数学公式用 `$...$`。

### 5.4 文件与上传

| 项 | 规则 |
| --- | --- |
| 允许类型 | `image/jpeg`、`image/png`、`image/webp`、`application/pdf` |
| 大小 | 单文件 ≤20MB；单次上传 ≤10 个文件 |
| 嗅探 | 读文件头判定真实类型，不信任扩展名与 Content-Type |
| 存储 | `data/uploads/{yyyy}/{mm}/{uuid}.{ext}`，DB 记 `files` 行 |
| 命名 | UUID，杜绝原始文件名参与路径（防穿越） |
| 下载 | `GET /api/v1/files/{id}`，JWT 鉴权 + 归属校验；`Content-Disposition: inline` |
| 清理 | 试卷删除后文件保留 7 天，定时任务清理孤儿文件（P2） |

PDF 处理说明：
- 优先用纯 Go 抽取文字层（`ledongthuc/pdf` 或自写解析），有文本则按文本块 + 版面顺序送入模型，成本低、准确率高。
- 无文字层（扫描件）：本期提示老师上传页面截图；P2 再引入服务端渲染（可选外部 `pdftoppm`/pdfium，需在配置中显式开启，保持默认纯 Go）。

### 5.5 判分引擎

```
提交 → 事务内锁定 attempt（submitted）
     → 遍历题目：客观题本地判分写 attempt_answers
     → 存在主观题且 paper.ai_grading=1：状态 grading，投递 jobs(attempt_grade)
     → 否则：汇总分数，状态 graded
Worker → 取未判主观题 → 批量 AI 评分 → 写分数/评语 → 汇总
       → 生成报告（本地统计 + AI 总结）→ graded
```

- 汇总口径：`score = Σ(每题得分)`；`objective_score`、`subjective_score` 分别统计；空答记 0。
- 幂等：重复提交返回当前状态；worker 重复执行覆盖同题结果而非累加。
- 失败可重试：`jobs.attempts < 3`，状态 `grading → failed` 时可"重新阅卷"。

### 5.6 异步任务

- 表 `jobs` 持久化，进程内 worker pool（默认 3）消费。
- 启动时把 `running` 状态回滚为 `pending`，实现重启恢复。
- 任务类型：`paper_parse`、`attempt_grade`、`report_regen`。
- 进度：`progress 0~100` + `message`，前端 2s 轮询（解析）/ 3s 轮询（阅卷）。
- 同一试卷同一时刻只允许一个解析任务；同一答卷只允许一个阅卷任务（DB 唯一索引 + 应用层校验）。

## 9. 安全设计

| 风险 | 措施 |
| --- | --- |
| 口令泄露 | bcrypt；不回显；日志不打印密码；改密后 `token_version+1` |
| 令牌滥用 | HS256 + `exp` 30 天 + `ver`；密钥首次生成存 `data/.secret`（0600）或环境变量；支持一键全员下线（P1） |
| 越权 | 中间件角色校验 + Service 层资源归属校验（答卷/文件/试卷） |
| SQL 注入 | GORM 条件构造与参数绑定；`Raw` 仅用于内部统计且必带 `?` 参数；排序字段白名单映射，禁止拼接用户输入 |
| XSS | 前端统一转义；后端不返回 HTML；上传文件强制 `Content-Type` + `X-Content-Type-Options: nosniff` |
| 路径穿越 | 存储名 UUID，原始名仅存库；下载按 ID 取路径并校验前缀 |
| 恶意上传 | 类型嗅探 + 大小限制 + 图片解码校验（`image.DecodeConfig`） |
| 暴力破解 | 登录限流（IP+用户名，10 次/分钟）+ 失败计数锁定（P1） |
| 密钥泄漏 | API Key AES-GCM 加密，DB 中无明文；接口脱敏 |
| CSRF | 使用 Bearer Token，非 Cookie，无语义风险；CORS 默认同源，跨域需显式配置 |
| 敏感日志 | 请求体不落日志（仅路径/状态/耗时）；AI 请求只记摘要与用量 |

## 10. 错误处理与可观测性

## 13. 部署与运维

### 13.1 构建
```bash
go build -trimpath -ldflags "-s -w" -o onlineTest ./cmd/server
# 交叉编译示例
GOOS=linux GOARCH=amd64 CGO_ENABLED=0 go build -trimpath -ldflags "-s -w" -o onlineTest ./cmd/server
```

### 13.2 配置（优先级：flag > env > config.yaml > 默认）
| 项 | 默认 | 说明 |
| --- | --- | --- |
| `--addr` | `:8080` | 监听地址 |
| `--data-dir` | `./data` | DB、上传、日志 |
| `--config` | `./config.yaml` | 可选 |
| `ONLINETEST_SECRET` | 自动生成 | JWT/加密主密钥（32B base64/hex） |
| `ONLINETEST_JWT_DAYS` | `30` | 令牌有效期 |
| `ONLINETEST_UPLOAD_MB` | `20` | 单文件上限 |
| `ONLINETEST_LOG_LEVEL` | `info` | debug/info/warn/error |

### 13.3 首次启动
1. 创建 `data/`、`data/uploads/`、`data/logs/`。
2. `AutoMigrate` 建表/索引/CHECK → 补充索引 DDL（组合/部分索引）→ seed（科目、设置、初始老师账号）。
3. 若无老师账号：创建 `admin`，随机密码打印一次日志，并置 `must_change_password`。
4. 启动 HTTP，输出版本与监听地址。

### 13.4 备份与升级
- 备份：停止写入或执行 `PRAGMA wal_checkpoint(TRUNCATE)` 后复制 `app.db` + `uploads/`；提供 `scripts/backup.*` 说明（P2 自动化）。
- 升级：替换二进制 → 启动时先 `AutoMigrate`（只增）→ 执行补充 DDL/数据迁移 → 结构变化超出增量范围时拒绝启动并提示先跑手工迁移。
- 回滚：保留上一版本二进制与备份数据目录。

### 13.5 反向代理
- 生产建议 Nginx/Caddy 终止 TLS，`client_max_body_size 25m`，SSE/长请求超时 ≥180s。

## 14. 风险与应对

| # | 风险 | 影响 | 应对 |
| --- | --- | --- | --- |
| R1 | 扫描版 PDF 无文字层，纯 Go 无法栅格化 | 上传即失败 | 明确引导上传图片；P2 支持外部渲染工具（配置开启）；前端预先提示 |
| R2 | AI 结构化输出不稳定（截断/多包代码块/夹杂解释） | 解析失败 | JSON 模式 + 平衡括号提取 + 修复器 + 重试；失败保留摘要；校对页人工兜底 |
| R3 | 数学公式/手写体 OCR 准确率有限 | 题目错误 | 置信度标记 + 校对页高亮低置信题目；答案缺失显式标红；老师必须确认后发布 |
| R4 | 主观题评分一致性/争议 | 用户信任 | 低温度、明确评分细则、给出扣分依据、分数步长 0.5、老师可人工改分 |
| R5 | AI 成本与限流 | 体验/费用 | 题目批量、图片压缩（长边 1600、JPEG 0.85）、并发上限、调用日志与用量统计 |
| R6 | SQLite 写并发 | `database is locked` | 单写者设计、事务短小、WAL + busy_timeout、批量写走 `CreateInBatches`/`OnConflict`、必要时应用层互斥与 busy 重试 |
| R7 | 长请求（AI 120s）被代理断开 | 后台任务失败 | 解析/阅卷全部异步化，HTTP 请求只做入队与轮询 |
| R8 | 试卷修改影响已有作答 | 数据不一致 | 已发布试卷限制编辑范围 + 二次确认 + 记录快照（P1：作答时快照题目） |
| R9 | 零打包前端的可维护性 | 开发效率 | 明确模块边界与组件约定、统一渲染函数、禁止内联脚本；控制单文件 <300 行 |
| R10 | 公式编辑器（contenteditable + MathLive）跨浏览器差异、移动端键盘遮挡 | 作答体验 | 只在做题/编辑页懒加载；公式节点不可编辑 + 浮层编辑；降级 textarea；重点测 Chrome/Edge/Safari |
| R11 | MathLive 资源体积（mjs + 字体）影响首屏 | 加载慢 | 懒加载 + 本地 vendor + 缓存头；首屏不引入公式包 |

## 15. 验收标准

1. 老师可登录，创建学生账号，学生可用该账号登录并完成一份试卷。
2. 老师可配置任意 OpenAI 兼容模型，测试连通性成功，密钥在数据库中为密文。
3. 上传图片/文本型 PDF 试卷，AI 能识别出 ≥90% 的题目（抽样 3 份），校对页可修正并发布。
4. 学生答题自动保存，刷新/断网恢复后答案不丢；客观题提交即出分。
5. 主观题在 60 秒内完成 AI 阅卷，给出逐题评语与整卷建议；AI 故障时不影响出分且有明确标记。
6. 老师端可查看成绩与报告；学生只能看到自己的数据（越权测试通过）。
7. 单二进制部署，`go test ./...` 通过，重启后任务可恢复、数据不丢。
8. 数学解答题可在网页内用公式编辑器完成混排（文字 + 公式），刷新后完整恢复；移动端可调出虚拟键盘输入常用符号。
